[1] WORK : AI INVOICE AUTOMATION (CERBI)

Titan Aviation Fuels / Python, Claude API / in production

An invoice automation platform. It reads scanned and handwritten carrier invoices, works out what each one is, files the complete ones and imports them into the ERP, and puts the rest in front of a person with the reason it stopped.

[>] Try the invoice automation simulation (Cerbi) (interactive, fictional data)

THROUGHPUT
hundreds of invoices a day
INPUT
scanned and handwritten, not just clean PDFs

-- ONE INVOICE, END TO END --

  1. 01 Ingest freight paperwork from email (shared mailboxes through Microsoft Graph), carrier and telematics APIs, and drop folders.
  2. 02 Identify who sent each invoice, using sender rules, known aliases and the ERP’s orders.
  3. 03 Extract the loads on every page: each document goes to Anthropic’s Claude API with a prompt for its document type, and comes back as structured JSON. Prompts are built for caching and documents are sent in batches to keep cost down.
  4. 04 Validate each invoice against the business rules, in order.
  5. 05 Review anything incomplete in a review inbox, with a short reason why it stopped.
  6. 06 File everything complete, and import it into the ERP.

-- DESIGN DECISIONS --

  • A person sees what the machine can’t decide. Nothing is guessed or silently dropped. An invoice that fails a check stops in a review inbox with a short, plain reason, so the fix is a decision, not an investigation.
  • Measure, then scale. Extraction cost and field coverage were measured on real documents before the full backlog was run, and every figure in the design is labelled as measured or estimated.
  • Built to be operated. Integrated with Microsoft Graph, the Samsara API and the company’s ERP; deployed on IIS with CI on GitHub Actions, so changes ship the same way every time.
